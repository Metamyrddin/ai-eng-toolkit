## How to read these results (hand-written)

* **Retrieval:** BM25 and the dense MiniLM model are statistically indistinguishable on SciFact nDCG@10 (paired CI for dense − BM25 straddles 0); dense has the better Recall@100. Reciprocal-rank fusion improves on both (paired intervals exclude 0) and has the best recall. The weighted-score hybrid has the highest nDCG@10 in this run; we did **not** tune its weight on held-out data, so treat it as a lower-evidence result than RRF, which has no tunable score weights.
* **Cross-encoder reranking did not help here**: `hybrid_rrf+rerank − hybrid_rrf` is ≈ 0 with an interval spanning 0, while latency per query is ~19× higher. `ms-marco-MiniLM` was trained on web-search queries, which may transfer poorly to scientific-claim retrieval (untested explanation); we report the negative result rather than a different reranker chosen after seeing the outcome.
* **RAG:** with a 0.5 B generator, every citation the model wrote pointed to a passage that was really in its context (`citation_validity`), but only part of the answers contained any citation, and the gold abstract reached the prompt in `context_recall@k` of the queries. Sample answers (in the JSON) show the model often says "the documents do not address the claim" — SciFact claims are hard for such a small model. **No claim of answer correctness is made.**
* **Agent:** valid tool-call JSON in all calls; calculator and unit conversion mostly succeed; search is hit-or-miss (the agent's own query found the gold paper in most but not all cases, and it then often failed to name it); on questions that need **no** tool it still called a tool most of the time — a typical failure of very small models. n per category is 5–10, so the Wilson intervals are wide (see table). The calculator failure on "(45 + 55) / 4" is a real error of the model: it dropped the parentheses when writing the tool call.
